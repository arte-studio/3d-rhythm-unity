# 新しい曲の拍・小節の頭・区切りを決める手順

工大祭版（2026-10）では，拍と小節の頭を決めるまでに何度もやり直した．そのとき分かった落とし穴をもとに，
**解析ツール → AI が読む → 人が聴き比べて決める** の順で，最短で決める手順をまとめる．
決めたあとの直し方（譜面エディタ，テンポ表）は `music-data.md`．

## 手順（30 分くらい）

1. **解析する**（1 分）．`3d-rhythm-unity` で:

   ```sh
   py 3d-rhythmgame/BeatTool~/beatgrid.py <音声ファイル> --out 3d-rhythmgame/Builds/beatgrid
   ```

   必要なものは Python と numpy，ffmpeg．`Builds/beatgrid` に次のファイルができる．
   - `report.md`: テンポ，拍の位置，区間ごとのずれ，1 拍目の候補，区切りの候補
   - `click_*.wav`: 聴き比べ用のクリック音（高い音 = 1 拍目）
   - `result.json`: 数字だけ

2. **AI（Claude）にレポートを読ませる**．例:「`Builds/beatgrid/report.md` を読んで，テンポ・拍・1 拍目の候補を確かめて」．
   AI は次のことを確かめる．
   - テンポの候補が半分や 2 倍になっていないか
   - 区間ごとのずれが 30ms を超えていないか（超えるならテンポを少し変えるか，途中でテンポを変える）
   - 1 拍目の候補の点がどれくらい離れているか（近いなら聴き比べる候補を増やす）
   - 必要なら `--bpm` や `--excerpt`（聴く範囲）を変えて，もう一度解析する

3. **人が聴き比べる**（5〜10 分）．`click_1_…wav` から順に聴く．
   - 太鼓（ドン・タン）とクリックがぴったり重なって聞こえるか
   - 高い音で小節が始まって聞こえるか

   どれも違うときは，一番近いものを選び，「拍は合っているが高い音が 2 拍目に来る」のように**何拍ずれているか**を伝える．
   工大祭版も，これで 1 回で決まった．

4. **譜面エディタに入れる**．BPM と「1小節目(秒)」を入れて保存する．
   区切りや演出をもう置いてあるときは「区切りと演出だけ動かす」を選ぶ（ノーツは耳で置いたものなら動かさない）．

5. **区切りを置く**．レポートの「区切りの候補」（音色や和音がまとまって変わる小節）をもとに，
   譜面エディタのメトロノーム（M）を鳴らしながら聴いて，区切りの帯を右クリックして置く．区切りはふつう小節の頭に置く．

6. **曲の最初から最後までメトロノームで聴く**．後半でずれていくならテンポ表で直す．

## 工大祭版でずれた理由（落とし穴）

| 落とし穴 | 何が起きたか | 手順のどこで防ぐか |
| --- | --- | --- |
| テンポの半分・2 倍 | 最初の解析ではテンポを 76 BPM と検出し，2 倍の 152 にした．2 倍にすると，どの拍が 1 拍目かの手がかりが無くなる | 1，2（候補を全部出し，AI が確かめる） |
| 表拍と裏拍 | 曲に半拍ごとの音がはっきりあると，「拍」の候補が半拍ずれて 2 通りできる．解析の数字だけでは決まらない | 3（両方の格子を聴き比べる） |
| 1 拍目 | この曲は 1 小節目の 1 拍目に強い音が無い（グリッサンドのあと 2・3・4 拍目に音が来る）．最初の予測は 1 拍ずれていた | 1（和音の変わり目と低音で順位を付ける），3（耳で決める） |
| 叩くと早くなる | 拍を待ち構えて叩くので，叩いて求めた拍の位置は音より 60〜80ms 早かった．半拍ごとの音につられた分も混ざった | 叩いた値は拍の位置には使わない |
| 粗い解析 | 最初の解析は区切りを探すためのもので，拍の位置は 71ms ずれていた | 1（立ち上がりを 3ms 刻みで見る） |

工大祭版の結果は 151.96 BPM，1 小節目 1.435 秒（耳で決めた）．ツールの 1 位の候補は 151.98 BPM，1.427 秒で，ほぼ同じだった．

## 叩いてテンポを合わせる機能（B・N キー）の使いどころ

- 向いている: テンポが分からないときに大まかに知る．1 拍目がどこかを人の感覚で示す（N を 1 拍目で叩く）
- 向いていない: 拍の位置を ms 単位で決める（叩いた拍は早めに出る）．位置は解析と聴き比べで決める

## ツールの中身（beatgrid.py）

外部のライブラリを使わず，研究でよく使われる基本の手法を組み合わせている．

1. **立ち上がり**: スペクトルフラックス（周波数ごとの対数振幅の増えた分の合計．2.9ms 刻み）
2. **テンポ**: 立ち上がりの自己相関で候補を出し，位相の集中度（拍の周期で丸めた位置がどれだけ揃うか）で 0.01 BPM まで詰める
3. **拍の位置**: 半拍の周期で立ち上がりの平均の位置（円周の平均）を取る．区間ごとに見てずれがないかも確かめる
4. **1 拍目**: 拍の格子 2 通り × 拍子の数の候補を，和音の変わりやすさ（クロマの変化）と低音の強さで順位付けする
5. **区切り**: 小節ごとの音色と和音の自己類似行列に，チェッカーボードのカーネルを掛ける（Foote の novelty）

## もっと精度がほしいとき（試していない）

- **Beat This!**（CPJKU，ISMIR 2024）: 拍と 1 拍目を同時に求める新しい手法．PyTorch が要る．`pip install beat_this`
- **madmom** の `DBNDownBeatTracker`: RNN と DBN で 1 拍目まで求める定番．新しい Python では入らないことがあるので，Python 3.10 くらいの仮想環境で使う
- **librosa** の `beat.beat_track`: 動的計画法による拍の推定．1 拍目は求めない
- **Sonic Visualiser** と QM Vamp Plugins の Bar and Beat Tracker: 画面で波形と拍を重ねて見られる．音楽に詳しい人向け
- DAW（Ableton Live のワープマーカーなど）で拍を合わせてもらい，その数字を譜面エディタに入れてもよい

これらの結果も，report.md と一緒に AI に読ませて突き合わせ，最後は聴き比べで決める．
