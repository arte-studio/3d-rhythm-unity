# 3D リズムゲーム 仕様書（v2）

リングの内側に立った観客（子ども）が，光るモジュールにタッチして遊ぶリズムゲーム．
周りを囲むテープ LED（演出用）とノーツモジュール（むぎゅっと＋つながるノーツ）が音楽に合わせて光る．

- この仕様書は v2（2026-10 の作り直し）の仕様．旧版の仕様書は `docs/legacy/SPECIFICATION-v1.md`（旧版の実装の説明．判定幅・ノーツの色など
  一部は v2 で「旧仕様書の意図」として採った）．
- 作り直しの経緯・決定事項・各段階の詳細は `docs/architecture-v2.md`．
- 寸法・配線・設営ごとの違いの正は `3d-rhythmgame/Assets/Rhythm/Data/Hardware/` の JSON（説明は `docs/hardware/README.md`）．
- 演出の大本は初期の演出仕様書（`docs/effects/original-spec.md`）．

## 1. ゲーム

| 項目 | 仕様 |
| --- | --- |
| 曲 | 1 曲 約 90 秒（古代祭版: 「星座になれたら」をモチーフにしたオリジナル曲，151.96 BPM） |
| ノーツ | タッチノーツ（光ったモジュールに触れる）．譜面の形式にはつながるノーツ（connect）もあるが，今の譜面には無く判定もしない |
| レーン | 0 始まり（画面では 1 始まり）．どのレーンがどのモジュールかは設営ごと（`setups/*.json` の `lanes`） |
| 判定 | 5 章 |
| 遊ぶ人 | 子ども．リングの内側に立つ |

## 2. 全体の構成

```text
ノート PC（本番．Ryzen 7 5800U，ローカルで動かす）
  Unity（Play シーン）: 曲の再生と時刻，判定，演出の描画（GPU），ノーツ用 LED，送信
    │  Wi-Fi（UDP．プロトコル v2）
    ├─ ESP32-S3 × 8 台（デバイス 0〜7）: テープ LED 4 系統，タッチセンサー 5 個
    └─ （任意）別の PC の Viewer.exe: 同じ LED のデータを受け取って暗幕の部屋を再現（ミラー）
```

- マイコンは ESP32-S3（XIAO）に統一．ファームは `3d-rhythm-lowlayer-program/tape_led_module_s3`（v2.2）．
- 本番は強い Wi-Fi ルーターを使う（家庭用ルーターでは非圧縮の 60fps が詰まることがあった）．

## 3. ハードウェア

### 3.1 デバイス（ESP32-S3）

| 項目 | 仕様 |
| --- | --- |
| 台数 | 8（番号 0〜7．番号は基板の NVS に保存．接続モニタ F2 から割り当てられる） |
| LED 出力 | 4 系統（ピン 0〜2 = 演出用，ピン 3 = ノーツ用）．NeoPXL8 で同時に送る．1 系統最大 480 個 |
| タッチ | 5 個．1ms ごとに読み，チャタリングを除いて，変化した時刻（デバイスの時刻）付きで送る |
| ポート | デバイス 8888，PC 9999 |

### 3.2 演出用 LED

| 項目 | 仕様 |
| --- | --- |
| テープ | 1 本 120 個（2m，60 個/m）．WS2812B（視野角 120°） |
| 本数 | 90 本（3 つの輪 × 30 本）．設営によって外す（kodaisai-1101 は 4 本外して 86 本） |
| 向き | リングの内側（中心の縦の軸）へ水平に向く．光は正面から cos で弱まり，裏には出ない |
| 配線 | 1 系統に 4 本．ジグザグ（上から配線するテープがある）．キャンバスの列 → 配線は `PerfLayout` |

### 3.3 ノーツモジュール

| 項目 | 仕様 |
| --- | --- |
| 構成 | むぎゅっと（8×8 = 64 個）＋つながるノーツ用テープ（30 個）．1 モジュール 94 個 |
| 数 | 1 デバイス最大 5 個．設営ごとに付ける場所が違う（kodaisai-1101 は 11 個） |
| 置き場所 | 設営データの `modules`．内側から見て左から右へレーン番号順．テープは次のむぎゅっとへ伸び，0 番目の LED は若い番号の側 |
| 色の並び | つながるノーツ用テープは R と G が入れ替わっている（送るときに入れ替える） |

### 3.4 明るさと色

- 明るさは PC が掛けてから送る（`出力 = (c × (b + 1)) >> 8`）．デバイスは届いた値をそのまま出す．
  デバイスの明るさの設定は，デバイスが自分で光らせるもの（タッチのピンク表示，自己診断表示）にだけ使う．
- 本番の明るさは演出用 50，ノーツ用 50（眩しいので下げている）．各色 51 段階になる．
- 色の曲線（設営データの `outputCurve`）: 既定は **srgb**（色を画面で見える値とみなし，光量に直してから送る．LED の見た目が画面の絵に近い）．
  `linear` は旧版と同じ（送る値に比例して光るので画面より白っぽい）．

## 4. ソフトウェア

| 層 | 場所 | 中身 |
| --- | --- | --- |
| Core | `Assets/Rhythm/Core` | Unity に依存しない C#．ハードの配置と配線，曲データとテンポ，判定，ノーツ用 LED，通信，Viewer の計算．`dotnet test 3d-rhythmgame/CoreTests~` で確かめる |
| Runtime | `Assets/Rhythm/Runtime` | Unity．曲の再生と時刻，判定のつなぎ，実機との通信，演出の描画，Viewer |
| Editor | `Assets/Rhythm/Editor` | 譜面エディタ，テンポ表，Timeline の道具，プレビュー書き出し，シーンとビルドを作る道具 |
| 道具 | `3d-rhythmgame/LinkTool~` | Unity なしで実機とつなぐコマンド（テスト表示，通信の計測，ミラー） |

シーン: `Assets/Rhythm/Scenes/Play.unity`（本番），`Viewer.unity`（別 PC で見る）．`Tools/Arte Rhythm/Create … Scene` で作り直せる．
旧版のスクリプト（`Assets/Script`）とシーン（`Assets/Scenes/SampleScene.unity`）は参考として残してある（同じポートを使うので同じシーンに置かない）．

## 5. 判定

d = タッチ時刻 − ノーツ時刻（秒）．既定は旧仕様書の判定幅（2026-10-27 ユーザー決定）．

| 結果 | 条件 | 得点 |
| --- | --- | --- |
| Perfect | \|d\| ≦ 0.05 | 100 |
| Good | 0.05 < \|d\| ≦ 0.15 | 50 |
| Miss | d > 0.15 までタッチが無い | 0 |

- 判定はタッチの押し始めだけ．触れたままでは次のノーツは取れない．同じレーンの 0.1 秒以内の再タッチは無視．
- 1 回のタッチで判定するのは，そのレーンの最も早い未判定のノーツだけ．
- 子ども向けに緩めるときは曲ごとに song.json の `rules` に書く（`perfectSec`，`goodSec`，`missAfterSec` など）．
  旧版の値（Perfect −2.0〜+0.5 秒，Good −3.0〜−2.0 秒，得点 5/3）は `JudgeRules.Legacy()`．
- タッチの時刻はデバイスの時刻を PC の時刻に直して使う（7 章）．遊んだタッチはリプレイとして保存する．

## 6. ノーツ用 LED

色は旧仕様書の意図，速さなどは旧版の値（2026-10-27 ユーザー決定．`NoteLedStyle`）．

| 状態 | 表示 |
| --- | --- |
| 案内 | ノーツ時刻の 3 秒前から，むぎゅっとが青く点滅（周期 0.5 秒，ノーツ時刻にちょうど点く位相） |
| Perfect | 緑（最初の 0.2 秒はむぎゅっとに虹色の回転） |
| Good | 黄 |
| Miss | 赤 |
| 判定のあと | むぎゅっとは 0.5 秒でフェードアウト．同じレーンのつながるノーツ用テープに判定色の光を流す（3 秒，18 個/秒） |
| 曲の間 | 全レーンのつながるノーツ用テープを色相（210°〜296°）を変えながら塗っていく（60 個/秒）．曲が終わったら消える |
| タッチ | デバイスが自分で 3 秒間むぎゅっとをピンクにする（旧ファームと同じ．タッチの演出が決まったら PC で描くようにしたい） |

## 7. 曲と時刻

- 曲のデータは `Assets/Rhythm/Songs/<曲>/song.json`（`SongAsset` が音声・動画・Timeline とまとめる）．

| 項目 | 中身 |
| --- | --- |
| `tempo` | テンポ表（1 行目の `t` が 1 小節目の頭．途中で変わるなら行を足す） |
| `sections` | 曲の区切り（前奏，A メロ…）．演出・譜面づくりの共通の呼び方 |
| `notes` | ノーツ（`t` 秒，`lane`，`type`） |
| `rules` | この曲だけ判定を変えるとき |
| `audioStartSec`，`videoOffsetSec` | 音声・動画と曲時刻のずれ |

- 曲時刻はオーディオの DSP 時刻から作る．曲は少し先の時刻に予約して鳴らし，その時刻を曲頭にする．
- `inputLatencySec`（タッチが届くまで），`outputLatencySec`（LED が光るまで）は設営ごとに測って入れる．
  演出は LED の遅れを見込んで先回りして描く．光は音より少し早いほうが自然（遅れると目立つ）．
- タッチの時刻: PC が PING を送ってデバイスとの時計のずれを測り（往復が最も短いものを使う），デバイスの時刻を PC の時刻に直す．
- 古代祭版: 151.96 BPM，4 拍子，1 小節目 1.435 秒．区切りは前奏 0〜8 小節，A メロ 9，B メロ 17，サビ1 27，
  サビ前 41，サビ2 43，最後 51（2026-10-28 に耳で確定．`docs/authoring/music-data.md`）．

## 8. 演出（演出用 LED）

- **キャンバス**: 横 = テープの列（90），縦 = 1 本の LED（120．下が 0）の絵を GPU で描き，読み戻して配線順に送る．
  土台（カメラ・動画）に演出を重ねる（普通 / 足す / 掛ける / 明るい方）．色は画面で見える値．
- **Timeline**: 曲ごとの Timeline（`SongAsset.timeline`）に「LED 演出」トラックを並べ，クリップ（演出のマテリアル）を置く．
  一番上の「曲（小節と区切り）」トラックに小節と区切りの目印が付く．クリップの位置は小節・拍で表示・入力でき，
  テンポを直すと同じ小節・拍のまま付いてくる．
- **演出に渡す値**: 曲の時刻，拍・小節，曲の音量（0〜1），各ピクセルの LED の 3D 位置，クリップの時刻（`Shaders/ArteLed.cginc`）．
- **テンプレート** 13 種（`Assets/Rhythm/Effects/Templates`）: 単色，グラデーション，拍で光る，波紋 3D，面 3D，きらめき，画像，
  螺旋の上昇，流れ星，星空，柔らかい点滅，回りながら色が変わる，下の波．
- **古代祭版**: 初期の演出仕様書から下書きを並べた（`docs/effects/kodaisai-2025.md`）．旧版の演出動画は参考．
- 作り方の手引き（美大生向け）は `docs/authoring/led-effects.md`．

## 9. 通信（プロトコル v2）

詳細は `3d-rhythm-lowlayer-program/docs/protocol-v2.md`．

| 方向 | 種類 |
| --- | --- |
| PC → デバイス | WELCOME（つながった），PING（時計合わせ），PIXELS（LED．1 ピン 1 パケット），CONFIG（明るさなど），SET_ID（番号を変える） |
| デバイス → PC | HELLO（見つけて），PONG，TOUCH（時刻付きのタッチ．直近 8 件を毎回送り直す），STATUS |

- フレーム番号と「このフレームで送るピン」を付け，デバイスは揃ったら表示する（揃わなければ 50ms 待って表示）．
- 通信量を減らす: 変わっていないピンは送らない（0.5 秒ごとに 1 本ずつ送り直す），同じ色が続くところはまとめる（PackBits）．
- ミラー: 同じ PIXELS を別の PC の Viewer にも送れる（`DeviceLink.mirrorTo`，起動引数 `-mirror`）．つながっていないデバイスの分も送る．
- 混み具合で送る頻度を下げる仕組み（`LinkOptions.AdaptiveRate`）もあるが，本番は強いルーターを使うので既定は切ってある．

## 10. Viewer（シミュレーション）

- 実機に送るのと同じ値を光量として HDR で描き，ブルームとトーンマップで画面に出す．LED の向きと配光（cos）も再現する．
- 暗幕の部屋: 床・暗幕・テープ本体を LED の光だけで照らす．床と暗幕は設営データの `room` で選ぶ
  （床: グレーのカーペット / 白い床（学校）/ コンクリート．暗幕: 一般的な黒い暗幕）．
- 視点: リングの中心の子ども・大人の目の高さ，外から，真上から．歩いて見回せる．
- VR（Meta Quest 3）は計画だけ（`docs/architecture-v2.md` の P6）．

## 12. 設営

設営ごとのデータは `Assets/Rhythm/Data/Hardware/setups/<名前>.json`:
外したテープ（`removedStrips`），レーンとモジュールの対応（`lanes`），モジュールの置き場所（`modules`），
明るさ（`brightnessPerf`，`brightnessNote`），色の曲線（`outputCurve`），部屋（`room`）．

## 13. 決まっていないこと

- 曲の拍・区切りの確定（音楽に詳しい人に確かめる）
- 演出: サビ前の色，アクセントの点滅をどこに入れるか，ChatGPT の補足を採るか（`docs/effects/kodaisai-2025.md`）
- 判定幅を子ども向けにどこまで緩めるか（試遊のリプレイを見て）
- 各レーンのモジュールの実際の置き場所（kodaisai-1101 は旧版の配置から仮に作った）
- 会場の大きさ（暗幕までの距離と高さ）
- `inputLatencySec`・`outputLatencySec` を会場で測る手順
- タッチしたときのピンク表示（タッチの演出が決まったら PC で描く）
