# AI（Claude）による古代祭版の演出案 A・B・C

2026-10-28 の夜に，Claude が一人で「作る → 書き出す → 評価する → 直す」を 6 回くり返して作った演出案．
ねらいは，AI がどこまで演出を作り・評価できるか（今の AI の限界）を知ること．人の手直しの出発点としても使える．

- **見るもの**: `3d-rhythmgame/Recordings/ai-proposals/`（git には入れていない．作り直し方は最後の章）
  - `00_比較_3案と下書き（LEDの絵を一周ひらいたもの）.mp4`: 3 案と元の下書きを縦に並べた動画（曲の音つき）．**まずこれ**
  - `A_…`〜`C_…`: 子どもの目の高さから見た動画，光の譜面，コマの一覧，評価の数値
  - `切り替わり（サビ1・サビ2・最後の前後）.png`: 大事な切り替わりの前後 3 拍
- **Unity で見る**: Play シーンを再生して **F9** で演出を切り替える（下書き → 案A → 案B → 案C）
- **Timeline**: `Assets/Rhythm/Effects/kodaisai-2025-ai/A`〜`C`．組み立てるコードは `Editor/EffectProposals.cs`

## 1. 作り方（調べたことと，取り入れたこと）

最近の研究と現場の作り方を調べ，次の形にした．

| 調べたこと | 取り入れたこと |
| --- | --- |
| AI で MV を作る仕組み（MV-Crafter，MVWeaver，DIRECT など）は，**構想 → 展開 → 場面 → ショット** と上から順に決め，場面やショットの境目を拍・小節の頭・強い立ち上がりに寄せる | 案ごとに「構想（テーマと繰り返す絵）→ 曲全体の流れ → 区切りごとの場面 → きっかけ（クリップ）」の順に決めた．クリップの境目は小節の頭とアクセントに置いた |
| MVWeaver は，決めたことごとに「曲のどこが根拠か → 何を決めたか → ねらう効果」を残すと，曲に合った MV になった | 下の表に場面ごとの根拠と決めたこととねらいを書いた（後で人が直すときの手がかり） |
| ダンスの自動生成は，**同じ動きの単位を変化させながら繰り返す**と良くなる | 案ごとに主題（星座，オーロラ，回る光）を決め，場面ごとに数・速さ・色を変えて繰り返した |
| 照明の自動生成（Skip-BART，ICLR 2026）は，人が付けた照明が「意外性」で AI より高かった．照明は規則だけでは決まらない | アルゴリズムは候補を出すだけにし，どれを使うか，どこで我慢してどこで驚かせるかは AI（Claude）が決めた |
| ライブの照明の手引き: 曲の構成で見た目（ルック）を変える．毎拍・毎リフで光らせると，どの曲も同じに見える．A メロを抑えるとサビが大きく感じる | 拍で光らせるのはサビだけ．A・B メロは抑えた |
| VJ: 低音・高音などの帯域を，明るさ・色・動きにつなぎ，なめらかにする | 曲の音量で波やオーロラの明るさを変える．アクセントは帯域で色を変える（低音 = ピンク） |

**アルゴリズムと AI の分担**:

1. **曲の特徴（アルゴリズム）**: `EffectEval~/music_features.py` が，拍ごとの音量，強い立ち上がり（142 個），**際立ち**（同じ拍の位置のいつもの音に対する強さ．2・4 拍目のスネアのように毎小節鳴る音は 1 くらい）を出す．
2. **演出を組み立てる（AI）**: `EffectProposals.cs` に，案ごとの構想と場面を Claude がコードとして書いた．アクセントは「際立ちが一定以上のものを，強い順に，間をあけて，拍で光らせていない場面だけ」選んでヒットを置く．
3. **書き出す**: Play.exe でキャンバス（LED に送る絵）と画面を 1 フレームずつ書き出す（1 曲 40 秒）．
4. **評価（アルゴリズム + AI）**: `EffectEval~/evaluate.py` が数値と図を出し，Claude が図を見て観点ごとに採点して直す．

新しく作った演出テンプレート: **Hit**（アクセントで 1 回光る．全体 / 下から / 上から / 左右に広がる / 波紋），**Aurora**（オーロラ），
**Constellation**（星をつないで星座を描く），**Beam**（子どもの周りを回る光）．Starfield には明るさのばらつき（本物の星空のように）を足した．

## 2. 評価のしかた

研究では，AI の審査員に「総合点」を聞くより，**観点を分けて採点**させたほうが人の評価に近い（観点ごとに分けた評価を合わせると，一番良い 1 人の審査員より相関が上がる）．
観点は Skip-BART の人による評価の 6 つ（感情の一致，見た目のインパクト，リズムの同期，移り変わりの滑らかさ，没入感，意外性）に，
この作品で欠かせない 3 つ（**安全**，**仕様書への忠実さ**，**ゲームの見やすさ**）を足した．

数値（`evaluate.py`）:

- **安全**: 光の点滅（WCAG 2.3.1 に近い数え方．明るさが 10% 以上変わって戻るのを 1 回．1 秒に 3 回を超えたら NG．子どもが見るので必ず守る）
- **音と光の同期**: 光のアタック（はっきり明るくなる瞬間）が拍・音の立ち上がりの上に来る割合，強いアクセントで光る割合
- **盛り上がり**: 小節ごとの音量と光の強さの順位相関
- **区切り**: 区切りでの見た目の変わり方（ふつうの小節の境目の何倍か），場面どうしの違い
- **動きと場所**: 動きの量，場所によるムラ

図: **光の譜面**（曲全体を 1 枚に．横 = 時刻，上段 = 高さ方向，中段 = 一周方向，下段 = 音量・明るさ・動き），
**コマの一覧**（2 小節ごと），**切り替わりの帯**（大事な切り替わりの前後を細かく）．Claude は動画を見られないので，これらで判断した．

## 3. Claude のおすすめ

1. **案B 夜明け**（いちばんのおすすめ）: 曲全体が 1 つの物語になり，抑えた A・B メロがサビを大きく見せる．ゲームのノーツも見やすい．
   弱いところ: 前奏〜B メロが暗く（光の量 0.04〜0.06），単調に感じるかもしれない．拍との一体感は薄い．
2. **案A 星座**: 初期の演出仕様書をいちばん忠実に形にした．作者の意図から外れたくないならこれ．
   弱いところ: サビが明るくて一周同じ色の時間が長い．アクセントの点滅（仕様書の「??」）はほとんど入っていない．
3. **案C 鼓動**: いちばん音楽に乗れる．子どもが体を動かしたくなるのはこれ．
   弱いところ: ずっと動いていて区切りが分かりにくい．ゲーム中は気が散るかもしれない．

組み合わせるなら，**B の流れ（暗い A・B メロ → 暗転 → 日の出）に，C のサビ2 の回る光を入れる**のが良いと思う．

### 場面ごとの根拠と決めたこと（案B の例）

| 場面 | 曲の根拠 | 決めたこと | ねらい |
| --- | --- | --- | --- |
| 前奏 0 小節 | 最初の音（0.46 秒）からグリッサンド | 白い細い光が 3 周の螺旋で駆け上がる | 「始まる」合図．仕様書の螺旋階段 |
| 前奏〜A メロ | 音量 0.68 → 0.47（A メロで下がる） | 夜空に星が 4 小節かけて灯り，5 小節からピンクのオーロラ | 静かに見入る．あとのサビとの対比 |
| B メロ | 音量が上がる（0.66） | オーロラが青く高くなり，19〜24 小節で星座を描く | 曲名「星座になれたら」．盛り上がりへの準備 |
| 26 小節 4 拍目 | 26 小節 3.5 拍目に曲でいちばん際立つ低音のアクセント（際立ち 4.8） | 星を残したまま最後の 1 拍だけ暗転 | サビの入りを最大にする「ため」 |
| サビ1 | 音量 0.90（最大） | 日の出の空（下が暖色，上が青）．下から光が昇る | 夜明けの物語の山場 |
| サビ前 41〜42 | デクレッシェンド → クレッシェンド | 夕暮れの紫に沈み，下から光がせり上がる | 2 度目の日の出への準備 |
| サビ2 | サビ1 と同じ強さ | 始まりに全体がぱっと明るく，オーロラと流れ星，2 小節ごとに光が左右へ | 同じ主題を大きくして繰り返す |
| 最後 | 音量が 0.27 へ下がる | 夜に戻り，B メロの星座が空に残って消えていく | 物語を閉じる |

案A・C の根拠は `EffectProposals.cs` の各案の始めのコメントと，場面ごとのコメントにある．

## 4. くり返しで直したこと（AI が自分で見つけた問題）

| 回 | 見つけたこと | 直したこと |
| --- | --- | --- |
| 基準 | **画面の HUD の文字やボタンが LED のキャンバスに描かれていた**（録画したキャンバスに写っていた） | `LedCanvas` で Blit のあとに描き込み先を戻した（本体の不具合．実機への送信は HUD より前に読むので影響は小さいはず） |
| 基準 | 下書きのサビは全面がほぼ真っ白（光の量 0.83〜0.94）で模様がなく，星も見えない．星空は多すぎて砂嵐のよう | サビを眩しすぎない明るさにして模様を残す．星を少なくし明るさをばらつかせる |
| v1 | 星座のシェーダーがコンパイルできなかった（HLSL の予約語） | 名前を変えた |
| v1 | 案B の前奏〜A メロが真っ暗（0.02）．案C のサビ前が見えない | 明るさと太さを直した |
| v2 | 案A の点滅が 1 秒に 3 回を超えた．原因は 2 拍ごとの光とアクセントのヒットの重なり | 拍で光らせている場面にはヒットを置かない決まりにした |
| v3 | 案A のサビ2 の「薄い黄色」がオリーブ色に見えた（黄色を暗くすると濁る） | 暗くせず白に近い暖色にした |
| v3 | 案B のオーロラに四角い段差．ノイズが一周でつながっていなかった | 一周でつながるノイズにした |
| v3 | 案C のサビは土台が明るく，回る光が埋もれた．2 つのサビが似ていた | 土台を暗く．サビ2 は白とピンクの光を逆に回して交差させた |
| v5 | 案B のサビ前が 1 小節まるごと真っ暗（ねらいは 1 拍） | 星を暗転の直前まで残した |

## 5. わかった AI の限界

- **音が聞こえない**: Claude は曲を聞けない．曲の理解は，解析した数値（拍，音量，アクセント）と，人が付けた区切りの名前と仕様書の言葉だけ．
  メロディや歌詞の意味，「ここは切ない」といった感じ方は分からない．アクセントの「際立ち」も，静かな最後の場面ではちょっとした音で大きくなる．
- **動画が見えない**: 見られるのは静止画だけ．動きの気持ちよさ，速さ，酔いやすさは，数値と細かく並べたコマから推測した．
- **自分の作品の評価**: 自分で作ったものを自分で採点しているので甘くなりやすい（研究でも，AI は自分の出力を正しく直せないことがあると言われている）．
  数値の評価で補ったが，数値は「好み」ではない．最後は人が見て決める必要がある．
- **見つけられたのは「間違い」**: 不具合（HUD，段差，オリーブ色，真っ暗な 1 小節，点滅の重なり）は数値と図でかなり見つけられた．
  一方で「もっと美しくするには」は，研究や手引きの一般論から考えるしかなく，突き抜けた案は出にくい（Skip-BART でも「意外性」は人が上だった）．
- **シミュレーターの見た目**: Viewer の画面は LED の明るさ（50/255）をそのまま描くのでかなり暗く写る．暗い部屋で目が慣れた見え方とは違うはず．
  目の慣れ（自動露出）を入れると，評価も人の感じ方に近づく．
- **実機で確かめていない**: LED の色の出方（srgb の曲線，明るさ 50）や，部屋の中での眩しさは実機で見る必要がある．

## 6. 作り直し方・次にやること

```sh
# 3d-rhythmgame で（Unity を閉じてから）
py EffectEval~/music_features.py Assets/GameMusic.wav --song Assets/Rhythm/Songs/kodaisai-2025/song.json --out Assets/Rhythm/Effects/kodaisai-2025-ai/music.json
sh EffectEval~/cycle.sh v7         # 組み立て → ビルド → 3 案を録画して評価（5 分くらい）．数値の比べは compare.py
py EffectEval~/filmstrip.py Recordings/eval/切り替わり.png v7_A v7_B v7_C --at 27.1 43.1 51.1 --span 3
py EffectEval~/compare_video.py Recordings/eval/比較.mp4 "v7_A:案A" "v7_B:案B" "v7_C:案C" --audio Assets/GameMusic.wav
```

（録画と評価は `Recordings/eval/` に書く．git には入れない）

- 気に入った案を手で直すときは，`kodaisai-2025-ai/<案>` をフォルダごと複製して，曲の SongAsset の timeline に入れる（`EffectProposals` を実行すると案のフォルダは作り直される）
- 次にやるとよいこと: 人が 3 案を見て好みを付ける → その理由を Claude に伝えて次の案に反映（人の評価を取り込むくり返し）．
  Viewer に目の慣れを入れる．実機で 1 場面ずつ確かめる．
